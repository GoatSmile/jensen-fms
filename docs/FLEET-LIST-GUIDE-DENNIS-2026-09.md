# The fleet list — how to fill in the spreadsheet

**For Dennis, 24 September 2026.** This goes with the spreadsheet
*FLEET-LIST-DENNIS-2026-09.xlsx*. It is how the bikes already out with your
customers get into the system, so repair orders can be attached to them.

**Before you start: if the information already exists somewhere — customer
Excel sheets, delivery notes, e-conomic exports — send that instead.** Don't
retype it; I will do the sorting. Use the spreadsheet for what lives only on
paper or in your head.

| Tab | What it is | You… |

## Bikes — one row per bike

Not "10 × white Norma" on one line — ten lines. Each bike gets its own repair
history, so each one needs its own row.

**Only the two orange columns are required.**

| Column | Required? | What to put |
|---|---|---|
| **Customer** | **yes** | Pick from the drop-down |
| Site / department | if it matters | The building, depot or hotel the bike lives at |
| **Frame number** | **yes, if known** | The *stelnummer*. Leave blank if nobody knows it |
| Customer's fleet number | optional | The number the customer painted or stuck on the bike themselves |
| Model | optional | Pick, or type an older model |
| Colour | optional | Pick, or type an older colour |
| Delivered (year) | optional | Roughly is fine |
| Status | optional | *In service* unless you know it is retired or stolen |
| Lock, battery, charger number | optional | Only if it is written down somewhere |
| GPS / tracker | optional | IMEI or AirTag, for bikes that have one |
| Other IDs | optional | Motor, display, QR — anything else printed on the bike |
| Notes | optional | Anything that does not fit the columns |

**Three rules that save us both time later:**

1. **A blank is fine; a guess is not.** A wrong frame number is worse than a
   missing one, because the system will trust it.
2. **Unknown frame number? Still add the bike.** Fill in what you do know —
   customer, site, fleet number — and leave the frame number blank. Finn
   confirms it the first time the bike comes in.
3. **Pick the customer from the list, don't type it.** A few names appear
   twice — *Rigshospitalet*, *Herlev SSP*, several *Nybolig* offices — so the
   list shows the e-conomic customer number after each name. That number is how I match
   the bike to the right customer. If a customer is not in the list at all,
   type the name and I will add them.

**Model and Colour** offer the current models and colours. An older bike may
be a model or colour that isn't listed — just type it. The sheet asks once
whether you meant to; say yes.

## Agreements — one row per scan

Scan each service agreement that is **still running** to PDF (a phone scanner
app is fine), one file per agreement, and name the file after the customer.
Then give each file a row here, so nothing gets lost between the scan and the
system.

| Column | What to put |
|---|---|
| Customer | Pick from the drop-down |
| Site / department | Only if the agreement is for one site, not the whole customer |
| Scan file name | Exactly as you saved it, e.g. *Rigshospitalet 2024.pdf* |
| Still active? | Yes / No / Not sure |
| **Covers ALL their bikes?** | Yes / No — **if No, say which bikes in Notes** |
| Notes | Anything agreed that isn't written in the paper |

I read each agreement into the system myself and send you a short summary to
check — you don't have to type out what the agreements say. The one column
that really matters is **Covers ALL their bikes?**: today the system assumes
an agreement covers every bike the customer (or that site) has, and I need to
know about any that don't before anything is loaded.
